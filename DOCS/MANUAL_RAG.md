# Manual RAG — Workshop Manual Search & AI Context

AS500 integrates with the **as500-docs** microservice to provide retrieval-augmented generation (RAG) from ingested workshop manuals. When a user asks a question in the AI chat, the relevant manual excerpts are automatically fetched and injected into the agent's context.

---

## Architecture

```
User question (chat)
       │
       ▼
AS500 chatService.ts
       │  fetchDocsContext()
       ▼
as500-docs /search  (POST, internal Docker network)
       │
       ├── pgvector similarity search
       ├── keyword search (tsvector)
       └── cross-encoder reranker
       │
       ▼
Relevant chunks + citations
       │
       ▼
Injected as system message → as500-agent → LLM
```

The `docs` container runs inside the same Docker Compose stack as AS500 and is only reachable on the internal Docker network (`http://docs:8080`). It is **not** exposed publicly.

Embeddings are generated by **Ollama** (`nomic-embed-text`) running on the dev machine, reached via WireGuard VPN.

---

## Production Environment Variables

Add to `/var/www/AS500/.env`:

```bash
# ── as500-docs RAG service ─────────────────────────────────────────────────────
# Database URL for the docs container (shares the same postgres service)
DOCS_DATABASE_URL=postgresql+psycopg://as500:<password>@postgres:5432/as500

# Path inside the docs container where manual images are stored
DOCS_STORAGE_ROOT=/var/www/AS500/storage

# Internal URL of the docs service (app container reaches it via Docker network)
DOCS_API_URL=http://docs:8080

# Minimum relevance score for chunks to be included in the context (0–1)
DOCS_MIN_SCORE=0.25

# Ollama on the dev machine (over WireGuard VPN) — used for embeddings
OLLAMA_BASE_URL=http://172.30.0.5:11434
EMBEDDING_MODEL=nomic-embed-text
EMBEDDING_DIM=768
```

> **Important:** Ollama must be running on the dev machine with `OLLAMA_HOST=0.0.0.0` so it is reachable from the production server over WireGuard. Set this as a System environment variable and restart Ollama.

## Adding a New Manual

Manuals are ingested locally (where you have GPU and Ollama), then the resulting database rows and image files are pushed to production using the export script.

### Prerequisites

- Python 3.12 installed locally
- `as500-docs` running locally (`docker compose up -d postgres` in `C:\Users\fredr\code\as500-docs`)
- Ollama running with `nomic-embed-text` pulled
- For best results with Western-language PDFs: vLLM serving `ibm-granite/granite-docling-258M` (see below)

### Step 1 — Ingest the PDF

```powershell
cd C:\Users\fredr\code\as500-docs

# Set env
$env:DATABASE_URL="postgresql+psycopg://as500_docs:as500_docs@localhost:5434/as500_docs"
$env:STORAGE_ROOT="storage"
$env:EMBEDDING_BACKEND="ollama"
$env:EMBEDDING_MODEL="nomic-embed-text"
$env:EMBEDDING_DIM="768"
$env:OLLAMA_BASE_URL="http://localhost:11434"

# Standard pipeline (RapidOCR — works for all languages, no GPU needed)
$env:USE_VLM="false"
C:\Users\fredr\AppData\Local\Programs\Python\Python312\python.exe -m as500_docs.cli ingest `
  "path\to\manual.pdf" `
  --manufacturer "CFMOTO" --model "450 MT" --year 2024 `
  --title "CFMOTO 450 MT Service Manual 2024"

# VLM pipeline (granite-docling-258M via vLLM — higher quality for Western PDFs)
# First start vLLM: C:\Users\fredr\code\vLLM-5090\run-d.bat
$env:USE_VLM="true"
$env:VLM_API_URL="http://localhost:8000/v1"
C:\Users\fredr\AppData\Local\Programs\Python\Python312\python.exe -m as500_docs.cli ingest `
  "path\to\manual.pdf" `
  --manufacturer "Brand" --model "Model" --year 2024 `
  --title "Manual Title"
```

### Step 2 — For non-English manuals: translate + re-embed

Skip this step for English manuals.

```powershell
# Note the manual_id printed at the end of ingest, then:

# Translate chunk content, headings, and section paths to English
C:\Users\fredr\AppData\Local\Programs\Python\Python312\python.exe -m as500_docs.cli translate-manual `
  <manual_id> --to English --model "gemma4:31b-it-q4_K_M"

# Re-embed using translated text so English queries find the content
C:\Users\fredr\AppData\Local\Programs\Python\Python312\python.exe -m as500_docs.cli reembed-manual `
  <manual_id>
```

### Step 3 — Test locally

```powershell
# Keyword/vector search
C:\Users\fredr\AppData\Local\Programs\Python\Python312\python.exe -m as500_docs.cli search "engine oil change"

# Full RAG answer
$env:RAG_MODEL="gemma4:31b-it-q4_K_M"
C:\Users\fredr\AppData\Local\Programs\Python\Python312\python.exe -m as500_docs.cli ask `
  "What is the engine oil capacity?" --sources
```

### Step 4 — Push to production

```powershell
cd C:\Users\fredr\code\as500-docs
pwsh scripts\export-to-prod.ps1 -Target prod
```

This dumps the database tables and copies the image files to the production server. The docs service picks them up immediately — no restart needed.

## Deployment

The `docs` service is defined in `docker-compose.prod.yml` and deployed automatically alongside `app` whenever the AS500 Playwright CI passes and triggers the GitHub Actions deploy workflow.

To deploy manually:

```bash
ssh -i ~/.ssh/hetzner_ed25519 root@172.30.0.1
cd /var/www/as500-docs && git pull
cd /var/www/AS500
docker compose -f docker-compose.prod.yml build docs
docker compose -f docker-compose.prod.yml up -d docs
```

## Checking Status

```bash
# Container health
docker compose -f docker-compose.prod.yml ps

# Docs API health (from inside the app container)
docker exec as500-app-1 sh -c 'wget -qO- http://docs:8080/healthz'

# Live search activity
docker compose -f docker-compose.prod.yml logs app -f | grep docs
```

A healthy response looks like:
```json
{"status":"degraded","database":"ok","vlm_server":"error: ...","version":"0.1.0"}
```
`vlm_server: error` is expected in production — VLM is only used locally for ingestion.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `[docs] service unreachable: timeout` | Ollama not reachable from prod | Set `OLLAMA_HOST=0.0.0.0` and restart Ollama on dev machine |
| `[docs] service unreachable: timeout` (first query only) | Cross-encoder loading cold | Query again — subsequent calls are ~130ms |
| `[docs] query=... relevant=0` | Score below threshold | Lower `DOCS_MIN_SCORE` or check embeddings are in English |
| No `[docs]` log lines at all | `DOCS_API_URL` not set in container | Force-recreate app container: `docker compose up -d --force-recreate app` |
| `alembic: DuplicateTable` on startup | Tables pre-exist (e.g. after data push) | Run `alembic stamp head` inside docs container |
