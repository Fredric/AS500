
# **Admin UI Config System – Specification**

## **1. Core Concept**

  

A **developer-authored, TypeScript-typed configuration object** defines everything needed to render and operate a CRUD-style admin UI.

- UI code treats the config as the **single source of truth**
- The same config can drive:
    - Web UIs
    - Desktop apps
    - Terminal / prompt-driven interfaces
    - A simple listing 
- CRUD is implicit
- Additional actions are explicit   
- Presentation is UI-owned, **behavior is config-owned**
- One UI can be initialized with context 


    

---

## **2. Execution Model (Lifecycle)**

### **2.1 Initialization**

1. UI loads config
    
2. A **derived context** is created for this UI
    
3. All datasources defined in fieldConfigs are **eagerly loaded**
    

  

### **2.2 List Phase**

1. UI calls services.list(params(context))
    
2. Records are stored in context
    
3. UI decides how to display them
    

  

### **2.3 Selection**

- Selection is explicit and ordered:
    

```
context.selection: TRecord[]
```

### **2.4 Create**

1. UI calls getInitialValues(context)
    
2. Form is rendered using formBuilder
    
3. On submit:
    
    - services.create is called
        
    - Service mutates context
        
    - Returns created record
        
    

  

### **2.5 Edit**

1. selection[0] is the active record
    
2. Full record is sent to update
    
3. Service returns updated record
    

  

### **2.6 Delete**

- Implicit delete uses selection
    
- Confirmation is declarative
    

  

### **2.7 Actions**

- Global / Record / Bulk
    
- Receive full context
    
- Use same service mechanism
    

  

### **2.8 UI Composition**

- Opening another UI:
    
    - Creates a **derived context**
        
    - No shared mutation
        
    - Only one active UI at a time
        
    

---

## **3. Context Model**

```
export interface AdminContext<TRecord = any> {
  records?: TRecord[]
  selection: TRecord[]          // always array, ordered
  values?: Record<string, any>  // form state
  input?: Record<string, any>   // UI input params
  user?: any
  env?: 'client' | 'server'
}
```

### **Rules**

- **Only services may mutate context**
    
- Config functions are read-only
    
- Child UIs receive derived contexts
    

---

## **4. Service Contract**

```
export type ServiceMethod<TContext, TResult> =
  (context: TContext, params?: any) => Promise<TResult>

export interface ServiceCall<TContext> {
  service: any
  method: string
  params?: (context: TContext) => any
  transform?: (context: TContext) => void
}
```

### **Guarantees**

- Async
    
- JS objects only
    
- create / update return updated record
    

---

## **5. Field Configuration**

  

### **Boolean Expressions**

```
type BoolExpr<TContext> = boolean | ((context: TContext) => boolean)
```

### **Validators**

```
type Validator<TContext> = (context: TContext) => string | null
```

### **Datasource**

```
export interface DatasourceConfig<TContext> {
  service: any
  method: string
  params?: (context: TContext) => any
  valueField: string
  displayField: string
}
```

### **FieldConfig**

```
export interface FieldConfig<TRecord, TContext> {
  field: keyof TRecord
  label: string

  datasource?: DatasourceConfig<TContext>

  form?: {
    type: string
    visible?: BoolExpr<TContext>
    disabled?: BoolExpr<TContext>
    required?: BoolExpr<TContext>
    validators?: Validator<TContext>[]
  }

  column?: {
    cellRenderer?: (
      record: TRecord,
      datasource?: any[]
    ) => string | number
  }
}
```

---

## **6. Actions**

```
export interface ActionConfig<TContext> {
  label: string
  scope: 'global' | 'record' | 'bulk'

  service: any
  method: string
  params?: (context: TContext) => any

  visible?: BoolExpr<TContext>

  confirm?: {
    message: string | ((context: TContext) => string)
  }
}
```

- Declarative only
    
- UI decides how confirmation is shown
    

---

## **7. UI Composition**

```
export interface OpenUIConfig<TContext> {
  id: string
  mapContext: (parent: TContext) => TContext
}
```

- Derived context
    
- No shared mutation
    
- Stack/replace navigation
    

---

## **8. Main Config Interface**

```
export interface AdminUIConfig<TRecord, TContext> {
  id: string
  title: string

  services: {
    list: ServiceCall<TContext>
    create: ServiceCall<TContext>
    update: ServiceCall<TContext>
    delete: ServiceCall<TContext>
  }

  getInitialValues?: (context: TContext) => Partial<TRecord>

  fieldConfigs: Record<string, FieldConfig<TRecord, TContext>>

  columnBuilder: string[]
  formBuilder: string[]

  actions?: Record<string, ActionConfig<TContext>>

  openUI?: OpenUIConfig<TContext>
}
```

## **9. Fully Typed Users Example**

```
interface User {
  id: number
  name: string
  stateId: number
}

export const UsersUI: AdminUIConfig<User, AdminContext<User>> = {
  id: 'users',
  title: 'Users',

  services: {
    list: {
      service: UserMgmt,
      method: 'getAllUsers'
    },
    create: {
      service: UserMgmt,
      method: 'createUser'
    },
    update: {
      service: UserMgmt,
      method: 'updateUser'
    },
    delete: {
      service: UserMgmt,
      method: 'deleteUser'
    }
  },

  getInitialValues: () => ({
    stateId: 1
  }),

  fieldConfigs: {
    name: {
      field: 'name',
      label: 'Name',
      form: {
        type: 'text',
        required: true,
        validators: [
          ctx => ctx.values?.name ? null : 'Name is required'
        ]
      }
    },

    state: {
      field: 'stateId',
      label: 'State',
      datasource: {
        service: UserMgmt,
        method: 'getStates',
        valueField: 'id',
        displayField: 'name'
      },
      form: {
        type: 'select'
      },
      column: {
        cellRenderer: (record, ds) =>
          ds?.find(s => s.id === record.stateId)?.name ?? ''
      }
    }
  },

  columnBuilder: ['name', 'state'],
  formBuilder: ['name', 'state']
}
```

## **10. What You’ve Built**

  

This is:

- Not a CRUD generator
    
- Not a schema-driven form
    
- **A programmable admin runtime**
    

  

It’s closer to:

- COBOL screens
    
- AS/400 DDS
    
- Terminal command graphs
    

  

…but written in **modern TypeScript**, with zero UI lock-in.
